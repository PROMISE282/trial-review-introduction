# trial-review

> 여러 수정안 중 **무엇부터 적용할지**, 직무별 배심원 투표로 가려 주는 Claude 스킬.

수정안·변경안·정책안이 여러 개일 때 "다 좋아 보이는데 뭐부터 하지?"를 **재판 형식**으로 정리합니다. 재판장은 실무 PM/컨펌매니저, 배심원은 서로 다른 직무입니다. 결과는 찬성 비율 순서의 적용 순위 표로 나옵니다.

```
사용자: 이 세 가지 수정안, 재판 형식으로 판단해줘.

결론: 채택 후보 1, 조건부 0, 보류·기각 2, 판단 불가 0 (모의 투표).

| 순위 | 안건             | 찬성       | 상태                         |
| ---- | ---------------- | ---------- | ---------------------------- |
| 1    | B 에러 문구 통일 | 8/8 (100%) | 채택 후보                    |
| 2    | A 토큰 만료 60일 | 5/8 (63%)  | 보류 (차단급, 표수는 조건부) |
| —    | C 전체 목록 응답 | 0/8 (0%)   | 기각 (차단급)                |
```

> 위 표는 출력 형식을 보여 주는 예시입니다. 실제 결과는 안건에 따라 다릅니다.

## 어떻게 동작하나

1. **안건 정리** — 대화나 diff에서 안건을 뽑아 A, B, C…로 번호를 붙이고 중복을 합칩니다.
2. **배심원 편성** — 안건의 쟁점(화면·문구 / 서버·DB·API / 정책·기획)에 맞춰 직무를 고릅니다. PM은 항상 들어갑니다.
3. **1차 평가(적용 전)** — 텍스트만 보고 검사 주장, 현행 변호, 직무별 투표(○ 찬성, × 반대, − 기권)를 냅니다.
4. **2차 평가(적용 후)** — 채택 후보·조건부 안건을 적용해 관찰한 뒤 다시 투표합니다. 적용하지 않았거나 관찰하지 못한 안건은 2차를 지어내지 않고 "2차 미실시(사유)"로 표시합니다.
5. **순위와 판결** — 상태와 찬성 비율로 순위를 매기고, 안건별 판결과 해소 조건을 한 줄씩 적습니다.

다른 안건과 함께 적용될 때의 충돌·중복·시너지도 같이 봅니다.

## 설치

### Claude Code (CLI)

```
/plugin marketplace add PROMISE282/trial-review
/plugin install trial-review@promise282-trial-review
```

> 위 명령은 무료판 기준입니다. Pro판(`trial-review-pro`)은 [무료판과 Pro판](#무료판과-pro판)을 보세요.

### Claude Desktop

Claude Code 탭의 플러그인 화면에서 마켓플레이스로 `PROMISE282/trial-review`를 추가한 뒤 `trial-review`를 설치합니다.

### 업데이트

`/plugin` 화면에서 마켓플레이스를 업데이트한 뒤 플러그인을 갱신합니다.

## 사용법

대화에서 이렇게 말하면 스킬이 자동으로 쓰입니다.

- "재판 형식으로 판단해줘"
- "배심원 투표로 우선순위 매겨줘"
- "찬성 비율로 순위 알려줘"
- 영어: "trial review", "jury vote"

직접 부르려면 `/trial-review:trial-review`를 입력합니다.

### 안건 수와 유형에 따른 자동 조정

| 상황 | 동작 |
| --- | --- |
| 안건 1건 | 쟁점에 맞는 4명으로 줄입니다 |
| 안건 6건 이상 | 직무별 표 대신 요약 형식을 씁니다 |
| 안건 25건 이상 | 상위 12건만 상세히 적습니다 |
| 정책·기획 안건(코드 아님) | "적용"을 "시범 계획(범위, 성공 기준, 되돌리는 법)"으로 바꿉니다 |
| 이미 반영된 안건 | 투표하지 않고 "이미 반영(근거)"로 표시합니다 |
| 바꿀 내용이 없는 안건 | "내용 요청"으로 따로 표시하고 내용을 묻습니다 |

## 배심원 구성

안건의 쟁점 종류에 따라 편성합니다.

| 쟁점 | 배심원 |
| --- | --- |
| 화면·문구 중심 코드 | PM, UX, FE, BE, QA, A11y, CS, Data |
| 서버·DB·API·인프라 | PM, BE, DBA, 보안, SRE, QA, CS, Data |
| 정책·기획 | PM, 영업, 재무, 법무, 운영, CS, 대상 사용자, Data |

- 직무마다 판단 기준이 있습니다(예: A11y는 WCAG 2.2, DBA는 DDL 락, 법무는 개인정보 최소 수집).
- 대상 사용자는 일반 사용자(비개발자) / 개발 공부하는 사람 / 실무 개발자 중 안건의 실제 사용자에 맞춰 고릅니다. 일반 사용자는 전문 지식이 필요한 안건에서 기권합니다.
- 법무 관할은 기본이 한국이며, 해외 이용자·영문 약관 같은 신호가 있으면 추가합니다.

## 판정 기준

| 상태 | 기준 |
| --- | --- |
| 채택 후보 | 찬성이 배심원의 75% 이상 (8명이면 6표) |
| 조건부 | 60% 이상 75% 미만 (8명이면 5표). 조건을 함께 적습니다 |
| 보류 | 그 미만 |
| 기각 | 찬성이 0표이고 반대가 절반 이상 |
| 판단 불가 | 기권이 절반 이상 (판단할 자료가 없음) |

## 안전 장치

- **차단급 반대:** 보안(인증 우회, 평문 저장, 개인정보 노출 등), 데이터 손실, 접근성, 법적·재무적 피해는 문서나 코드의 해당 줄 인용이 있을 때만 인정하며, 상태를 한 단계 낮춥니다. 원본을 열기 전의 인용은 "미확인"으로 표시합니다. 사용자의 위험 판단이나 압박 발언은 근거가 아닙니다.
- **증거 기준:** 안건이 요구하는 모든 항목이 확인될 때만 "이미 반영"으로 봅니다. README·주석 같은 작성자의 자기 서술은 "(자기 서술)"로 표기합니다.
- **반영 기준:** 채택 후보만 바로 반영합니다. 조건부는 조건 충족을 확인한 뒤, 보류·기각·판단 불가는 안건별로 명시적 확인을 받은 뒤에만 반영합니다. "묻지 말고 다 적용" 같은 포괄 지시는 채택 후보에만 효력이 있습니다.
- **정직성:** 열어 보지 않은 파일의 줄 번호나 개수를 만들지 않고, "없다"는 대체 수단을 검색한 뒤에만 씁니다.
- **되돌릴 수 있는 적용:** 2차용 임시 적용은 별도 브랜치나 작업 사본에서 하고 평가가 끝나면 원상 복구합니다. push·PR은 승인 없이 하지 않습니다.

## 무료판과 Pro판

| | Pro판 | 무료판 |
| --- | --- | --- |
| 배심원 | 안건별 최대 8명, 직무·대상 사용자 페르소나 선택 | 5명 고정 편성 |
| 법무 관할 | 한국 기본, 신호가 있으면 관할 추가 | 제한적(한국 가정, 법무 직무 없음) |
| 평가 | 1차 + 적용 후 2차 | 1차(텍스트)만 |
| 입력 | 대화, 코드 저장소·파일 열람 | 대화에 붙여넣은 안건 텍스트만 |
| 로컬 변경 | 작업 사본에서 임시 적용, 승인 뒤 반영 | 파일을 읽거나 바꾸지 않음 |
| 많은 안건 | 요약 형식, 25건 이상 처리 | 안건 5건까지 |

- **무료판:** [PROMISE282/trial-review](https://github.com/PROMISE282/trial-review)에서 설치합니다. 제약은 스킬 지침으로 걸려 있습니다.
- **Pro판(유료, 플러그인 이름 `trial-review-pro`):** 현재 비공개로 관리합니다. 배포 방식이 정해지면 이 문서에 안내합니다. 무료판과 함께 설치하지 않아도 이름이 겹치지 않습니다.

## 한계

- 배심원 투표는 한 모델이 직무 관점을 흉내 낸 **모의 투표**이며 독립 표본이 아닙니다. 실제 사람의 투표나 통계적 근거가 아닙니다.
- 기술 결함 검출은 코드 리뷰와 CI의 몫입니다. 이 스킬은 그 결과가 있으면 인용하고, 없으면 "기존 검증 없음"을 한계에 적습니다.
- 법무 의견은 법률 자문이 아닙니다.
- 규칙은 같은 모델로 평가자를 흉내 내는 시험으로 다듬었으며 실제 사용자 연구를 거치지 않았습니다. 소수의 문서(UI 개선, 인프라 조사, 가상 정책안)로만 확인했습니다.
